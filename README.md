# PopOut

Connect-4 variant with *pop* moves, plus two AI players — one based on **Monte Carlo Tree Search** (MCTS) and another on an **ID3 decision tree** trained on MCTS self-play data.

Final project for the Artificial Intelligence course, FCUP, 2025/2026.

**Authors:** Miguel Almeida (up202303926), Francisco Passos (up202303922), Pedro Resende (up202207418).

---

## What's in this repository

- The PopOut game engine with the three special rules from the assignment (popper wins on simultaneous four-in-a-rows, draw on full board, draw on threefold repetition).
- A game loop that supports the three required modes: human-vs-human, human-vs-computer, computer-vs-computer (with two different algorithms).
- An MCTS player with UCT, resolved-subtree propagation, and an only-move shortcut. The random rollout is JIT-compiled with Numba (~50× speedup).
- An ID3 decision tree implemented from scratch (no `scikit-learn`), trained on two datasets:
  - **Iris** as a warm-up (4-bucket equal-frequency discretisation).
  - A self-play dataset generated by the optimised MCTS, where each row is a `(state, MCTS move)` pair.
- A script to generate the self-play dataset in parallel with multiple workers across multiple machines (bit-identical merge).
- A tournament runner for head-to-head comparisons between MCTS and DT configurations, with Wilson 95% confidence intervals.
- A `play.py` CLI that lets any combination of {human, MCTS, DT, random} face each other.
- A Jupyter notebook coordinating all experiments, results, and analysis. **This is the main deliverable.**
- Three audit reports under `_audits/` documenting the methodology and findings.
- A LaTeX presentation under `slides/` (PDF compiled from Beamer).

## Setup

Requires **Python ≥ 3.10**.

```bash
python -m pip install -r requirements.txt
```

The first import of `ai.rollout_numba` triggers a Numba JIT compile (~10-30 s). Subsequent runs use the on-disk cache.

## How to use

### View the main deliverable

```bash
jupyter notebook
```

Open `notebook.ipynb`. To regenerate all plots and outputs:

`Kernel → Restart & Run All`, then `Ctrl+S` to save.

### Play a single game (the three required modes)

`scripts/play.py` accepts any combination of `human`, `mcts`, `dt`, `random` for player 1 and player 2.

```bash
# Mode 1 — human vs human
python -m scripts.play --p1 human --p2 human

# Mode 2 — human vs computer
python -m scripts.play --p1 human --p2 mcts
python -m scripts.play --p1 human --p2 dt

# Mode 3 — computer vs computer (two different algorithms)
python -m scripts.play --p1 mcts --p2 dt
```

Optional flags:
- `--mcts-iter N` overrides the MCTS iteration count (default 20 000, the value validated by the D1 sweep)
- `--dt-pickle PATH` overrides the trained tree (default `data/id3/id3_tree_optimised_pruned.pkl`)
- `--seed N` controls the seed for stochastic players

### Re-run experiments

The committed CSVs in `data/tournaments/`, `data/sweeps/`, and `data/id3/` already contain the results. To reproduce them from scratch:

```bash
# 1. Generate the optimised self-play dataset (slow — distributed across machines for the original run)
python -m scripts.generate_dataset --iter 20000 --c 2.0 --num-children 1 --uct ucb1 \
    --num-games 150000 --output data/popout_dataset_150k.csv

# 2. ID3 hyperparameter sweep over both datasets (~1-2 h on 24 cores)
python -m scripts.sweep_id3 --workers 24 --output-dir data/sweeps --report _audits/sweep_results.md

# 3. Final ID3 evaluation: train 4 trees, 5-fold CV, 3 tournaments (~45 min on 24 cores)
python -m scripts.evaluate_id3 --workers 24 --output-dir data/id3 --report _audits/evaluation_results.md
```

### Run the tests

```bash
pytest tests/ -v
```

91 tests should pass.

## Key findings

A short summary of the main results documented in the notebook and the audit reports:

- **Optimal MCTS exploration weight `c` shifts with iteration count.** At 1 000 iter the textbook `c = √2` is reasonable; at 20 000 iter the optimum moves up to `c ≈ 2.0`.
- **Non-transitivity between UCB1 and UCB1-Tuned.** UCB1-Tuned beats the baseline MCTS more often than UCB1 does (70% vs 66%), yet UCB1 wins the direct head-to-head 60-40 / 237-163 (N=400).
- **A stronger MCTS does not produce a better imitation-learning decision tree.** The DT trained on the optimised MCTS dataset loses 0-200 (every game, both sides) head-to-head against the DT trained on the baseline MCTS dataset, despite the optimised MCTS winning 66-34 against the baseline MCTS.
- **Classification accuracy ≠ playing strength.** All four trained trees have cross-validated macro-F1 within 1 p.p., but tournament outcomes differ by orders of magnitude.

See `_audits/sweep_results.md` and `_audits/evaluation_results.md` for the supporting tables and discussion.
